# Backend API

This folder contains the Register inventory API. It is a Node.js/Express application using MongoDB through Mongoose. API controllers own request handling and persistence; routes attach endpoints and authentication middleware; models define persisted documents.

## Requirements and setup

- Node.js and npm
- MongoDB Atlas or another reachable MongoDB deployment
- A `backend/.env` file (ignored by Git)

Required environment variables:

| Key | Purpose |
| --- | --- |
| `MONGO_URI` or `MONGODB_URI` | MongoDB connection string. |
| `JWT_SECRET` | JWT signing key; must be at least 32 characters. |
| `ADMIN_EMAIL` | Initial admin email used by the seed script. |
| `ADMIN_PASSWORD` | Initial admin password; at least 8 characters. |

Optional variables: `ADMIN_NAME` (defaults to `Admin`), `PORT` (defaults to `5000`), and `CLIENT_ORIGIN` (defaults to `http://localhost:5173`). The application reads `backend/.env` via `dotenv`; do not place actual credentials in documentation or commit them.

```bash
npm install
npm run seed:admin   # run once when the users collection is empty
npm run dev          # development server with nodemon
npm start            # regular server
```

The server validates MongoDB URI and JWT secret on startup, connects to MongoDB, then starts listening. Stock movements use MongoDB transactions; use a replica-set deployment such as MongoDB Atlas for this operation.

## Single administrator and authentication

There is no registration route. `scripts/seedAdmin.js` creates the first user from `ADMIN_EMAIL`, `ADMIN_PASSWORD`, and optional `ADMIN_NAME`, hashes the password with bcrypt, and refuses to seed if a user already exists. `User.singletonKey` and the unique email index constrain the user collection to one admin identity.

`POST /api/auth/login` checks the submitted email/password and returns a JWT valid for 12 hours. `GET /api/auth/me` returns the identity in a valid bearer token. Protected category, product, and movement routers each apply `requireAuth` before their handlers.

Header format:

```http
Authorization: Bearer <token>
```

## API endpoints

All routes are prefixed with `/api`. Successful responses use JSON and include `success: true`; errors include `success: false` and a message.

### Authentication

| Method | Path | Access | Behavior |
| --- | --- | --- | --- |
| `POST` | `/auth/login` | Public | Body: `{ "email": "...", "password": "..." }`. Returns token and user profile. |
| `GET` | `/auth/me` | JWT | Returns current user profile. |

### Categories

| Method | Path | Behavior |
| --- | --- | --- |
| `GET` | `/categories` | Lists categories with product, unit, and inventory-value summaries, plus unassigned-product count. |
| `GET` | `/categories/:id` | Gets one category and its summary. |
| `POST` | `/categories` | Creates a category. Body: `{ "name": "...", "description": "..." }`. Category code is generated by the API. |
| `PUT` | `/categories/:id` | Updates category name/description. |
| `DELETE` | `/categories/:id` | Deletes a category only when no products reference it. |

### Products

| Method | Path | Behavior |
| --- | --- | --- |
| `GET` | `/products` | Lists products, including populated category name. |
| `GET` | `/products/:id` | Gets one product. |
| `POST` | `/products` | Creates a product. Requires name, unique SKU, valid `categoryId`, unit cost, unit of measure, minimum stock level; description and bin are optional. |
| `PUT` | `/products/:id` | Updates product details/category. Stock quantity is not edited here. |
| `DELETE` | `/products/:id` | Deletes a product only if its on-hand quantity is zero. |

### Stock movements

| Method | Path | Behavior |
| --- | --- | --- |
| `GET` | `/movements` | Lists movement records newest first. |
| `POST` | `/movements` | Records a stock movement and updates product stock atomically. |

Movement body:

```json
{
  "productId": "<MongoDB product id>",
  "type": "in",
  "quantity": 12,
  "date": "2026-10-16",
  "reason": "Purchase"
}
```

`type` is `in` or `out`; quantity must be a positive whole number. Stock-out cannot exceed available stock. Each record includes the product name/SKU snapshot, balance before and after, reason, date, creation timestamp, and authenticated user's email.

## Data models

- **User:** singleton key, unique normalized email, hidden password hash, name, timestamps.
- **Category:** unique generated code, unique name, description, timestamps.
- **Product:** name, unique uppercase SKU, required Category reference, unit cost (PKR), unit of measure, description, minimum level, bin, on-hand quantity, creator, timestamps.
- **Movement:** Product reference and historical name/SKU, `in`/`out` type, quantity, before/after balances, reason, date, actor, timestamps.

Mongoose schemas provide required fields, enums, ranges, and indexes. Controllers additionally validate IDs, inputs, referenced category/product existence, duplicate SKU/category errors, and business rules. The global error middleware masks unexpected internal errors with a generic 500 response.

## Source map

```text
app.js                         Express app, CORS/body parsing, router mounting, error handler
server.js                      Environment loading, MongoDB connection, HTTP listener
models/                        Mongoose schemas
controllers/                   Auth, user, category, product, and movement handlers
routes/                         API route declarations and per-router authentication
middleware/requireAuth.js       Bearer JWT verification
scripts/seedAdmin.js            One-time administrator creation
```

## Current scope

The API currently covers authentication, categories, products, and stock movements. Search, filtering, pagination, and dashboard aggregates are primarily handled in the frontend; there is no dashboard endpoint or CSV import endpoint. `npm test` is only the default placeholder script and does not run a test suite.
